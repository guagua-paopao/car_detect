## 产品目标

构建面向园区入口、停车场车道和固定道路监控的车辆二级属性分析服务。系统按轨迹而不是按单帧输出结果，支持低质量样本降级为 `unknown`。

## 冻结决策

1. 新建独立车辆项目，复用基础设施，不在人物处理器中增加车辆分支。
2. 采用车辆检测与车辆属性分类两级模型。
3. MVP 只识别车身类型和粗粒度颜色。
4. 一级检测池和二级属性池独立、有界。
5. 属性结果按轨迹进行多帧融合，每条轨迹最多发布一个最终事件。
6. 云端完成训练和 ONNX 导出，TensorRT Engine 在目标 Windows 机器构建。
7. 数据集按摄像头、视频段和车辆轨迹分组切分，禁止相邻帧泄漏。
8. 首版保持单 Worker 进程。

## 首版验收方向

- 双路 1080p RTSP，一级检测平均每路不低于 8 FPS
- 队列长度不持续增长
- 轨迹确认后属性稳定 P95 不高于 1.5 秒
- 事件写库 P95 不高于 2 秒
- 8 小时运行无崩溃、显存持续增长或旧 Run 结果串入
- 每条轨迹至多生成一个最终事件
- 断流、数据库暂不可用、Redis 重启、回调失败和 Worker 重启均有可解释状态

实际精度门槛必须在冻结的目标域数据集和唯一性能基线上重新验证，不能直接继承历史报告中的数字。

## 范围变更

品牌/车系、车牌 OCR、跨摄像头 ReID、多进程调度和商业部署均属于范围变更，必须单独评审。
